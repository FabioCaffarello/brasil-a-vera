## Resumo executivo

Wave 3 começou pela estabilização — o produto entregue na Wave 2 tinha 3 seções
"honestas mas vazias" em todos os 721 perfis (pares contraditórios, top 5
afinidade, alinhamento à bancada), OG image vazando `localhost:3000` em todas
as URLs sociais e ressalvas operacionais não-fechadas. Antes de adicionar
feature nova, o produto precisava ficar em estado **"sem vergonha de mostrar a
um jornalista"**.

O Sprint 3.0 entregou em 1 dia (escopo cirúrgico): bugs visíveis corrigidos,
auditoria empírica completa dos endpoints CSV/`/api/stats`/busca, suite de
regressão automatizada (21 testes novos), truncagem honesta via headers HTTP,
copy honesto eliminando o padrão "Pode ser que faltem dados…" de todas as
rotas públicas, tooltip acessível L1-L4, e QA mobile com fix de tap targets
WCAG 2.5.5. ROADMAP da Wave 3 reescrito em 5 sprints + 1 micro-wave; ADR-020
formaliza a permanência do monolito TypeScript revogando o alvo "Go via
Strangler Fig" do ADR-007.

## Achados-chave

### Cobertura `orientacao_bancada` — caminho (c) com nuance

A cobertura aparente de 1.21% (sobre 1.482 votações Câmara totais) era **erro
de denominador**. Sobre o denominador correto — votações **nominais** Câmara
(onde orientação faz sentido por design) — a cobertura é **94.74%** (18 de
19). Ingestão saudável; "gap" é estrutural do tipo de votação (Câmara vota
nominalmente só ~1.3% do tempo; restante é simbólico).

Senado: 0 orientações (esperado — API não publica, ver
[#83](https://github.com/FabioCaffarello/brasil-a-vera/issues/83)). Script
`ingestion/ops/diagnose-orientacoes.ts` permanece para revalidação periódica
nas próximas waves.

### LCP > 2.5s em 3 rotas (mobile)

Lighthouse mobile contra prod identificou:

| Rota | LCP |
|---|---|
| `/` | 2.8s ⚠️ |
| `/parlamentares` | 3.1s ⚠️ |
| `/partidos/[sigla]` | 2.8s ⚠️ |
| `/parlamentares/[id]` | 2.3s ✅ |
| `/proposicoes` | 2.2s ✅ |
| `/votacoes/[id]` | 1.6s ✅ |

Performance score geral excelente (94-99); CLS=0 em todas. Fix do LCP > 1 dia
→ aberto como [#114](https://github.com/FabioCaffarello/brasil-a-vera/issues/114)
para Sprint 3.1 (redesign de frontend).

### Truncagem honesta dos exports CSV

Antes: `/api/export/proposicoes` retornava silenciosamente subset (limite 1000)
sem indicar ao pesquisador que o total era 8.852. Agora:

```
HTTP/2 200
x-total-count: 8852
x-returned-count: 1000
x-truncated: true
```

Sem regressão para quem consome o CSV puro (Excel, pandas, etc) — headers
extras não interferem no parsing.
