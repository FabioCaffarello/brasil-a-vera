## Resumo executivo

Primeira sprint da Wave 5. Marca a passagem do projeto de
**single-maintainer** para **multi-contribuidor**: versiona `.claude/`
como infraestrutura de time, instala governança humana em `.github/`,
e configura branch protection no `main`.

A Sprint 5.0 não toca código de domínio nem alterar funcionalidade
para o cidadão. Toda a entrega é de **infraestrutura colaborativa**:
permissões, hooks, agents, skills, onboarding, CODEOWNERS, issue
templates, security policy, dependabot.

Decisões guiadas por ADR-019 (gate de evidência): apenas peças com
problema concreto observado entram. 1 subagent (não 5), 6 skills
(cada uma com fluxo já repetido em PRs reais), 3 hooks
(deterministicamente testados).

## Achados-chave (Sprint 5.0)

### Versionar `.claude/` exige `.gitignore` cirúrgico

A inversão da decisão antiga (`.claude/` inteiro ignorado) custou um
bloco explícito de 5 padrões para o que **continua local**:
`settings.local.json`, `transcripts/`, `cache/`, `telemetry/`,
`.role-log`. Sem isso, contribuidor com transcripts locais empurraria
megas de histórico sem perceber. Documentado em PR 1.

### Hooks shell precisam de matriz determinística testada

`__tests__/test-hooks.sh` rodando 29 casos `(role, path) → exit code`
deu confiança para mergear o sistema de guard-rail sem deploy
preview manual. Comportamentos do `pre-commit-quality.sh` que
dependem de `git diff --cached` foram validados em sessão real com
modify+stage+revert controlado, output literal copiado para o PR.

### Vitest 3.2.4 expõe subcomando `related`, não flag

Comportamento confirmado empíricamente antes de escrever o hook:
`npx vitest related <files> --run`. Exit 0 em ambos "tests
encontrados e passaram" e "no test files found". Detecção via
`grep -q "No test files found"` no output diferencia os 2 casos
para o aviso amigável.

### `wave-2.0` no `notify-failure/action.yml` era bug, não label legacy

`gh issue list --label wave-2.0` mostrou 14 issues — 1 OPEN
(`#118 incident: ingestion-senado-senadores failed at 2026-05-14`).
A label estava sendo aplicada incorretamente em **incidentes pós
Wave 2.0**, contaminando dado histórico. Patch single-line removeu
do hard-coding; label preservada em `labels.yml` por ser
referenciada em issues fechadas legítimas.

### Subagent + skill wrapper resolve curadoria sem decorar checklist

`design-system-curator` (subagent) + `/add-primitive` (skill wrapper)
permite que qualquer contribuidor adicione primitiva sem decorar os
7 passos do ADR-021. Validação E2E adicionando `popover` com bundle
delta 0 KB (tree-shake até consumer real surgir).

### Branch protection em projeto solo precisa de escape

`enforce_admins: false` deliberado: owner como admin pode `--admin`
override em emergência (ex: hot-fix de produção). Quando o time
crescer, `enforce_admins: true` torna-se viável — documentado em
`BRANCH-PROTECTION.md` como plano de evolução.

## Decisões registradas durante a Sprint

### Default role é `designer`

Decisão alinhada ao prompt mestre §1.1: tudo que serve role menos
técnico deve continuar útil para o mais técnico, e nada feito para
engineer pode assumir conhecimento que designer não tem. Engineer
declara explicitamente `BAV_CLAUDE_ROLE=engineer` no shell rc.

### Apenas 1 subagent (não 5)

ADR-019 aplicado dentro do `.claude/`. `design-system-curator`
nasceu de evidência concreta (Wave 4 mostrou 10 primitivas
adicionadas seguindo 7 passos repetitivos). Subagents adicionais
esperam evidência similar.

### Skills > 200 linhas viram subagents

Regra registrada em `ONBOARDING-ENGINEER.md`. Evita super-skills
que acumulam contexto além do gerenciável.

### Hooks não duplicam Husky

`.husky/pre-commit` continua dono do Biome. Hook Claude
`pre-commit-quality.sh` roda apenas Vitest related, em domínio
disjunto. Feedback dentro da sessão Claude vale mais que erro
pós-sessão.

### Patch `notify-failure/action.yml` validado empíricamente

Criada issue de teste real (#177) com `--label "incident,ingestion"`
e fechada imediatamente. Output literal anexado ao PR 2. Princípio
13 honrado: 1 linha pode quebrar action consumida por 4 workflows
de ingestão — validação antes de mergear, sem fork necessário.

### CODEOWNERS enforcement OFF transitoriamente

`require_code_owner_reviews: false`. Decisão documentada em
`BRANCH-PROTECTION.md`. Ligará quando o time tiver 2+ handles
ativos por área. Hoje seria decorativo.

### Workflows advisory antes de required check

`pr-sanity.yml` e `design-tokens.yml` rodam mas não bloqueiam
merge. Promoção a required após 2 sprints com zero falsos
positivos. Princípio 13.

### Dependabot abriu 8 PRs no mesmo dia

Comportamento esperado pós-instalação (Sprint 5.0 PR 9). Owner
triará nos próximos dias. Limit configurado em 5 evita expansão
indefinida em ciclos seguintes.
