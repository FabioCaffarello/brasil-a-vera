# Probe — TSE candidaturas/bens 2026 (Wave 15-E.0)

**Data:** 2026-08-22
**Status:** parcial — fonte inacessível do ambiente local; probe definitivo deve rodar de GitHub Actions
**Contexto:** pré-requisito da Wave 15-E ([plano de consolidação](2026-08-plano-consolidacao-produto.md), §5). Princípio 13: output literal antes de código.

## O que se queria verificar

1. `consulta_cand_2026.zip` já publicado no CDN do TSE (registro de candidaturas fechou em meados de agosto/2026)?
2. `bem_candidato_2026.zip` publicado (4º pleito da trilha patrimonial)?
3. Formato/colunas compatíveis com os Zod schemas existentes (`ingestion/tse/candidatura-schema.ts`, `bem-schema.ts`)?

## Resultado literal

Todas as tentativas a partir do ambiente local (rede residencial, GIG) e de fetch cloud retornaram **403 do Akamai — inclusive para os arquivos de 2022 que a ingestão de junho/2026 baixava normalmente de GitHub Actions**:

```
$ curl -sI https://cdn.tse.jus.br/estatistica/sead/odsele/consulta_cand/consulta_cand_2026.zip
HTTP/2 403        # content-length: 464 (página "Access Denied" do Akamai)

$ curl -sI .../consulta_cand_2022.zip          # ← arquivo que EXISTE e já foi ingerido
HTTP/2 403

# Com User-Agent de navegador (Chrome 126): 403
# Via Chromium real (playwright-core + request.head): 403 (2022 e 2026)
# Portal CKAN dadosabertos.tse.jus.br via fetch cloud: 403
```

## Leitura

- O 403 **não distingue** "arquivo não publicado" de "arquivo existe": o bot manager do
  Akamai bloqueia o ambiente de probe por IP/fingerprint antes de resolver o path
  (o 2022, comprovadamente existente, também dá 403).
- O ambiente que importa é o **GitHub Actions** — é de lá que `ingestion/tse/tse-client.ts`
  roda, e de lá os downloads de 2014/2018/2022 funcionaram nas Waves 11/14.
- Bloqueio atual de escrita no Neon (incidente #768) **não impede** um probe de Actions:
  um `curl -sI` em workflow não toca banco.

## Próximo passo (Wave 15-E.0 definitivo)

Rodar de GitHub Actions, numa das duas formas:

1. **Preferida**: incluir no primeiro PR da Wave 15-E um workflow mínimo `probe-fonte.yml`
   (workflow_dispatch, input `url`, passo único `curl -sI`) — reusável para qualquer
   probe futuro de fonte. Lembrete: workflow novo só é dispatchável **após merge na main**
   (gotcha conhecido do `gh workflow run`).
2. Alternativa sem peça nova: aguardar o reset da cota Neon (01/09) e rodar a própria
   ingestão TSE com `ANO=2026` em dry-run/ambiente de teste.

Riscos que o probe definitivo deve cravar antes do ADR da 15-E: presença do arquivo 2026,
colunas novas vs schema Zod (eleição geral pode reintroduzir colunas ausentes em 2022),
tamanho (janela de download no runner) e encoding (Latin-1 + multiline, gotcha do Eixo 2).
